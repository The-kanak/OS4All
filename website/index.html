Project Motivation

Why Personal Baseline Intelligence Matters

Traditional health assessment relies primarily on static population reference ranges. OS4All explores personal physiological homeostatic baselines so subtle shifts don't go unnoticed.

Traditional healthcare metrics often notify an individual only after a value crosses an arbitrary statistical population threshold. Yet what is considered average across millions of people is not necessarily normal for you.

"Normal for the general population is not necessarily normal for the individual."

Subtle multi-day autonomic shifts—such as nocturnal Heart Rate Variability (HRV) suppression paired with a rising resting heart rate and fragmented slow-wave sleep—often precede noticeable physiological fatigue or acute strain by days.

OS4All provides an open-source architecture that models individual baselines from longitudinal wearable streams and uploaded lab reports, helping people understand shifts in their health data before important trends are overlooked.

Population Cutoffs vs. Personal Baseline

✕
Static Population Ranges: Flags metrics only when individuals cross broad statistical extremes, overlooking gradual internal drift.
✓
Personal Rolling Baseline: Computes individual confidence envelopes over 7+ days to detect meaningful deviations tailored to your physiology.
✕
Isolated Metric Silos: Vitals, sleep records, and laboratory reports are analyzed in separate disconnected dashboards.
✓
Multi-Signal Correlation: Correlates HRV, resting heart rate, sleep duration, and lab markers to highlight autonomic strain holistically.
✓
Doctor-Ready Talking Points: Translates data drift into structured, non-diagnostic questions for qualified clinical consultations.
System Capabilities

Core Platform Capabilities

All capabilities below are grounded in the verified repository implementation, with transparent distinction between local deterministic algorithms and external service integrations.

Implemented

Health Trend Monitoring

Continuously computes rolling statistical baselines (mean, median, standard deviation, interquartile range, confidence envelopes) across Resting Heart Rate, HRV, SpO2, sleep duration, and body temperature.

Engine: BaselineEngine.java (7+ day threshold)
Verified with Review

Medical Report Information & OCR

Ingests diagnostic laboratory documents (PDF, PNG, JPG/JPEG) with Apache PDFBox text extraction and heuristic biomarker parsing. Includes a human-in-the-loop review interface before committing any biomarker.

Engine: Apache PDFBox + Human Review Step
Live + Mock Fallback

AI-Assisted Health Information

5-agent intelligence layer orchestrating context extraction, trend analysis, and synthesis using NVIDIA Nemotron (via Nebius AI Studio). Enforces strict JSON Schema with a deterministic offline mock fallback.

Model: Llama-3.1-Nemotron-70B / Offline Mock
Implemented

Personal Health Overview

Unified cross-metric biometric dashboard presenting daily telemetry, historical trend envelopes, sleep architecture, and laboratory values in clean Material 3 visualizations.

UI: Flutter Material 3 Dashboard
Implemented

Preventive Health Awareness

Deterministic, rule-based cross-signal correlation engine flagging acute stress, cumulative autonomic fatigue, recovery deficits, and sustained multi-day baseline drift without black-box opacity.

Rule Engine: AnomalyDetectionService.java
Implemented

Privacy-Conscious Data Handling

Zero client-side secrets. Cryptographically hash-chained SHA-256 audit ledger tracking sensitive operations. Granular user opt-ins for data storage, AI inference, and evidence search.

Security: SHA-256 Audit Chaining & Consent
Live + Mock Fallback

Biomedical Literature Grounding

Curates biomedical references via Tavily Search, filtered strictly to peer-reviewed sources (PubMed, Nature, NEJM, AHA journals) with 0.65+ relevance threshold and offline mock fallback.

Evidence: Tavily Search / Mock Provider
Implemented

Native Google Health Connect

Direct Android Health Connect integration with runtime permission workflows and an in-memory deduplication ledger to prevent double-counting wearable sync records.

Android: API 28+ Google Health Connect
Transparent Workflow

How OS4All Works

A simple three-step approach grounded in transparent algorithms, human verification, and respectful clinical collaboration.

1

Explore Health Information

Sync continuous wearable telemetry (resting heart rate, nocturnal HRV, SpO2, sleep) via Google Health Connect, or upload diagnostic lab PDFs with human-in-the-loop verification.

✓ Requires user confirmation for extracted lab biomarkers before saving.
2

Review Trends & Relevant Insights

The deterministic baseline engine computes your 7+ day physiological envelope. When multi-signal drift occurs, AI agents summarize the variance grounded in peer-reviewed literature.

✓ Rule-based multi-signal correlation (no opaque black box).
3

Support Clinical Conversations

Use structured biometric summaries and physician talking points during your consultations with a doctor or qualified clinician to have an informed, objective discussion.

✓ Non-diagnostic information designed for collaboration.

Open Repository
PowerShell / Terminal 
# Prerequisites: JDK 17+, Maven 3.8+, Flutter SDK 3.47+, Git
git clone https://github.com/The-kanak/OS4All.git
cd OS4All

# Copy template environment file (backend defaults to offline mock mode)
Copy-Item .env.example .env
PowerShell / Backend Directory 
cd OS4All\backend

# Run 86 automated unit and integration tests
.\mvnw.cmd test

# Start Spring Boot backend (serves on http://localhost:8085)
.\mvnw.cmd spring-boot:run

# Health check: http://localhost:8085/actuator/health
# Swagger UI:   http://localhost:8085/swagger-ui.html
PowerShell / Frontend Directory 
cd OS4All\frontend

# Fetch Flutter dependencies
flutter pub get

# Run on connected Android device or emulator
flutter run -d android

# Or build local Android APK binary from source:
flutter build apk --release
Build from Source Notice: Pre-compiled binary releases (.apk) or Google Play Store listings are not currently hosted on GitHub Releases. The complete, unredacted open-source codebase is ready to build and run using Flutter SDK 3.47+ and JDK 17 as outlined in the setup steps above.
